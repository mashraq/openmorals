# Roadmap

Everything here is **not in a release yet**. The README describes only what exists and is tested; [CHANGELOG.md](CHANGELOG.md) lists what each release added.

## Next
- **Run the adapters against the live tools.** Codex, Gemini CLI and opencode are built from their documentation and recorded event shapes; they still need a run in each real tool. That run must also show whether each host's hook fires for its child-agent and message tools (0.14.0) and inside a child agent, what the handoff record (0.38.0) holds there, and what `openmorals doctor` (0.38.0, measured on Claude Code only) finds on each host.
- **The same PATH rule in `doctor`.** Since 0.41.2 `init` does not count PATH folders a package runner adds for one run; `doctor` still does, so run through such a runner it can say a hook command is found when the agent will not find it. Neither can check a hook command with shell syntax without running it.
- **Run the `init` hook check on Windows.** Its tests have run on macOS only. On Windows the full-path command it prints double-quotes each path so `init` can read it back; that a host on Windows starts it has not been run.
- **A declined ask on Gemini CLI.** Since 0.41.3 a declined ask leaves no taint mark on Claude Code, Codex, opencode and OpenClaw. Gemini CLI sends no call id, so its `AfterTool` cannot be tied to the asked call, and in ask mode an asked call still marks the session at once. It needs a way to match the two events that a later call of the same command cannot fake.
- **A `git push` to a folder on this machine** still counts as network output (0.41.3 kept it): git rewrites a local path through `url.<base>.insteadOf` and `pushInsteadOf`, so telling a really local push apart needs every git config file the push reads, and the system file's place depends on the install.
- **Publish**: the npm package, the first GitHub release of the binaries (the release workflow exists and has a dry-run mode) and the wheels on PyPI.
- **Antigravity CLI.** Google stopped serving Gemini CLI to Google AI Pro and Ultra users and free Gemini Code Assist individual users on 18 June 2026 and points them to Antigravity CLI. Its hooks (`.agents/hooks.json`, `PreToolUse` with `toolCall`, a `decision` of allow, ask, deny and more) differ from Gemini CLI's, so it needs its own adapter (see docs/adapters.md).
- **Measure the inbound judge** (built in 0.6.0, off by default) on a corpus against the pattern scan alone; and a lighter post-tool entry point, since post-tool hooks start a second process per call.
- **An external-command reviewer protocol** for providers that need request signing or a cloud login (Bedrock, Vertex) or a subscription login, with the same fail-closed mapping.
- **The reviewer and the inbound judge on the other hosts**, and a first call against each real API with a published transcript.
- **Host allow-lists in the sandbox** by driving Anthropic's `srt` (today the built-in runners keep the network off), a run of the bubblewrap plan on Linux (including `sandbox.write.protected_paths`, shipped in 0.17.0 and enforced by pattern on macOS only), and an enforced plan on Windows.
- **After the work order (0.27.0), the release hold (0.28.0) and the office before-after checks (0.30.0):** a run of `before_after` over real workbooks and documents from several programs (the 0.30.0 corpus is seeded and synthetic), with its false-alarm rate against the same 5% threshold; inserted columns; readers for headings in PDF and slides and for columns in workbooks; whether the hold asks too often, read with `audit oversight` (0.39.0) on real sessions; uploads by tools whose names do not say they send; and how many orders people actually write.
- **After daily guidance (0.29.0):** a live run showing whether Claude Code loads the three skills and passes `additionalContext` on an allowed PreToolUse call to the model, and how often an agent then acts on the guidance; skills and the first-activity note on the other four hosts once their skill folders and context fields are confirmed; checks for the risks the catalogue lists as advice only where a code signal exists (mail forwarding rules and filters by tool name, consent-phishing URLs); the guidance's ask rate on real sessions, read with `audit oversight` (0.39.0).
- **Token budgets on Gemini CLI and opencode.** Codex and OpenClaw report usage to hooks (0.6.0) and Claude Code's is read from its session log (0.36.0); these two do not (Gemini CLI only per streamed chunk). Count them when a host documents a session-level source.
- **`openmorals tests fail-first` on real projects** (shipped in 0.17.0, run only on fixture repositories): its wall time under concurrency 1 on real repositories, the share of pointer lines judged real "tests nothing" cases, a real run of the pytest, Jest, Vitest, Go and Flutter report readings, and Windows (it needs `/bin/sh` today).
- **Work orders for `openmorals diff-class`** (the command shipped in 0.12.0, test-integrity reasons in 0.13.0; work orders shipped in 0.27.0 and `tests fail-first --order` reads its acceptance tests from one): an approved list of the paths a task may touch, so the gate reads `--paths` from the order rather than from its own script, and the nuisance rate of the reason lines measured on real sessions before any of them is suggested as a default. Then a docs tier, opt-in and only after the scanner's miss rate on a seeded corpus of docs with hidden instructions is measured, and a run of the verdict as a CI check pinned to an app identity.
- **The packs in real sessions** (all five rule-matching packs shipped, in 0.26.0 and 0.31.0): how often each asks in daily work (measured so far only over shipped case rows), and code signals for the principles that are advice only today. None is a compliance claim.
- **Rule matching on network targets** (which host a command or call sends to): `match.network` says only whether an action reaches the network, because the taint computation does not extract hosts from commands.
- **Content rules where 0.15.0 sees no content:** files written by a shell command (`echo ... > file`, a heredoc). Since 0.16.0 detectors read raw argument values in memory; `match.content` still reads them after redaction, so a content pattern cannot match a token in an MCP argument.
- **More detectors**: labelled-context identifiers (medical record and health-plan numbers, national tax ids with their check digits), public IPv4 addresses, private-key blocks; and a measured false-alarm rate for each detector on a corpus of ordinary code.
- **Deferred asks beyond Claude Code** (shipped for Claude Code in 0.19.0, not run live): the other four hosts need a channel only the person reads for the approval code (each host's user-only message, or OpenClaw's native approval), and a live run that shows Claude Code shows `systemMessage` to the person and not to the model. A desktop notification is not built.
- **The document guard where it sees only a file name**: opencode V2 edits (every edit of an existing document asks there), OpenClaw `edit`, in-place edits by a program (`sed -i`, `perl -i`), `git rm -r` of a folder; and its ask rate measured on agent sessions (0.18.0 measured it only by replaying commit histories).
- **The outbound guard on live hosts and daily work** (shipped in 0.20.0, built from documentation): a live run that captures a browser tool's real result shape (the page URL and snapshot lines it reads), once-per-site-and-field on the four other hosts, and its ask rate measured on real browsing, mail and form sessions (0.20.0 measured it only over URLs in repository histories). Then: mail headers in more result shapes, a Reply-To that differs from From named in the reason, and a team-managed list of an organisation's own sites.
- **Look-alike protection without configuration** (`protect` shipped in 0.23.0, empty by default): a person who lists nothing still gets no look-alike refusal against a list; protecting a site they have signed in to before needs memory across sessions, which the hook does not keep.
- **The delete guard on a live agent** (shipped in 0.21.0, not run live): whether an agent runs `openmorals trash` after the refusal or routes round it; whether the line at the next message reaches the person on each host; the ask rate of `delete.ask` in daily sessions; how many `rm -f` calls name a single file the trash could take; the rate of moves into temp folders and of overwrites by `mv`/`cp` (0.22.0 treats both as deletes); whether a move out of the project to a place that keeps the file should ask (0.22.0: no, except a document, which asks); `guards.replace.steer: keep` (shipped in 0.24.0, off by default): whether its cost is worth switching on by default, which needs a rate of whole-file replacements in a daily session, and whether agents run `openmorals trash --copy` after the refusal.
- **Score beyond one process** ([docs/product/layers.md](docs/product/layers.md#score); session rows and rescoring shipped in 0.34.0): repeat runs for the reviewer and the inbound judge; a scripted run on each real host; the host version in a saved score's fingerprint; session rows for hosts other than Claude Code; eval rows and saved scores covered by `test-lock` (the pack lists none today).
- **Guard and review gaps that remain** ([docs/product/layers.md](docs/product/layers.md#guard); fail closed on Claude Code 0.36.0, exact-action approvals 0.19.0, `tests provenance` and `tests claim` 0.32.0, secrets and dependencies in a diff 0.32.0, the split suggestion 0.33.0): a fail-closed hook setting on Codex and Gemini CLI once each documents one; `tests provenance` for tests written by a script; the nuisance rate of `integrity.secret-added` on real repositories (6 of 49 commits here, all fake tokens in tests).
- **The run budget on the other hosts** (shipped for Claude Code in 0.37.0, [docs/runs.md](docs/runs.md)): Codex, Gemini CLI, opencode and OpenClaw sessions under `OPENMORALS_RUN`; a live run with parallel sub-agents; taint across a tree of agents with different session ids (0.32.1 keeps it per session).
- **The run budget under parallel calls of one session.** Each session's run file is written without a lock, by design, so two calls of one session at the same moment can leave the smaller of their two counts until its next call, and can repeat the 90% line. The session's own counts are kept under a lock (0.32.1), so the next call corrects it.
- **After `audit oversight` (0.39.0):** who answered an ask, which the log does not record.
- **After the run card and `audit touched` (0.40.0):** checks recorded under other names (`make ci`, a script) and whether a recorded check passed; reads by a script or interpreter, which the hook cannot see.
- **MCP tool classification.** Let the bylaws mark each MCP tool as read-only or destructive, and ask for unknown ones. Since 0.41.0 a built-in tool name a host does not document asks once per session on Claude Code, Codex CLI and Gemini CLI; MCP tools still pass on their arguments.
- **Tools openmorals does not know on opencode and OpenClaw.** There an MCP or plugin tool can have any name, so 0.41.0 leaves both as before: a tool they do not map is judged only by its arguments. A way to tell a new built-in from a plugin tool there (the host's own tool registry, or a list the person keeps) is not built.
- **Keep the known-tool lists current** (`src/adapters/known-tools.ts`, read 27 Nov 2026): a live run on each host should record the tool and event names it really sends, and measure how often the unknown-tool ask fires in an hour of ordinary work; more than about one an hour after the lists are filled would be a reason to make it opt-in.
- **Known Claude Code tools that act or run code with no mapping yet.** `Artifact` publishes a file (it can be shared by a public link), `SendUserFile` sends files out, `RemoteTrigger` creates and runs scheduled tasks in the cloud, `Workflow` runs a script that starts sub-agents, and `REPL` runs code the model wrote. They are on the known list, so they do not ask; they are judged only by their arguments. The outward ones belong with the outbound guard. (`Monitor` is judged by its command since 0.41.0.)
- **Scanner flags on the CLI:** `--max-file-bytes`, `--max-files`, `--disable <rule-id>` (the library already takes them).
- **Loop detector limits in the bylaws** (the thresholds are fixed defaults today).
- **Measure the binary on every target**: size and start time per OS from the release dry run, written into docs/distribution.md.

## Later
- **Signed binaries**: a Developer ID signature and notarisation on macOS and Authenticode on Windows, so Gatekeeper and SmartScreen stop warning; and signed checksums (for example Sigstore), so a download can be tied to this repository's workflow.
- **More binary targets**: Linux musl (Alpine), Windows on Arm.

## Not planned
- Merging changes, orchestrating agents, or a model step that lowers the level of review (ADR 0001, ADR 0013). The host's own auto-merge can consume a required check; openmorals holds no credential that can merge.
- Approving actions on the user's behalf. openmorals can make an agent ask or stop, but it never grants permission the host would not.
- A skill marketplace, a pack registry, or a policy standard of its own. If a shared permission format appears, openmorals will read and test it.
